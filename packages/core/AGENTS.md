# Core Package Guide

## Fork scope

Core is where this fork's own code lives. Fork-owned modules sit in dedicated directories so upstream files stay close to pristine: `src/plugin/fork/` (fork plugins, registered in `src/plugin/fork/index.ts`) and `src/session/fork/` (session-side overlays). Prefer a new fork file plus a single wiring edit over editing an upstream file — every upstream line this fork touches is a line the next sync may conflict on. When a merge conflicts on a deleted provider or desktop file, resolve it with `git rm` (ADR 0002, ADR 0005, ADR 0007).

## Tests

- Run `bun run test` from this package, never a bare `bun test`: the canonical runner (`script/test.ts`) sets the isolated `HOME` and XDG roots the suite depends on, and a direct run turns `preload.test.ts`'s isolation assertions into artifacts.
- Fork-only suites live beside their subjects (`test/plugin/fork/`, `test/fork/`), and `packages/core/test/plugin/supervisor.test.ts` pins the plugin-reload semantics the fork relies on.

## Known limitations

- **Project-local plugins execute without a prompt.** Opening a repository imports `.opencode/plugin/` and any `plugins` entry in its config (`src/config/plugin/source.ts:127-147` → `src/plugin/module.ts:120-124`), and MCP `command` servers from project config spawn asynchronously when a Location starts. The managed policy layer is the only veto and defaults to allow when nothing is configured (`src/plugin/module.ts:52-59`, `src/managed-policy.ts:69-77`). Use `OPENCODE_CONFIG_PROJECT_DISABLE=1` before opening an untrusted tree; it also disables this repo's own project config.
- **A project document can re-allow what a global document denied.** Permission rules scan last-match-wins and config documents load lowest-precedence first, so only a managed settings document (loaded last) outranks a project file; a configured deny still short-circuits saved approvals. Order and consequences: ADR 0008 and the trust-gate section of `PERSONAL.md`.
- **Opening a repository fetches every `references` remote its own config names.** A Location boot forks `Reference.refresh` (`src/reference.ts:106`, then hourly at `:112`), which clones or refreshes each configured `references.<name>.repository` through the repository cache (`src/repository-cache.ts`, `refresh: "daily"`): `git clone`, then `fetch --all --prune` + checkout + `reset --hard origin/main` under `~/.local/share/opencode/repos/<host>/<owner>/<repo>`. `Repository.parse` accepts scp-like (`git@host:path`), arbitrary-host https, and `github:owner/repo` forms (`src/repository.ts:47-77`), so the host is whatever the project config says; a failure is a logged warning, not an error. The resulting list is rendered into the agent's instructions with `name`, `path`, and `description` interpolated unescaped (`src/reference/instructions.ts:17-20`), and the fetched content stays readable at the cache path. `OPENCODE_CONFIG_PROJECT_DISABLE=1` is the only opt-out, so treat an untrusted tree as able to make the server dial a host of its choosing and to place text in the instruction block.
- **A project document can re-point a declared provider's endpoint, and the stored key follows it.** `providers.<id>.settings` merges over the global document (`src/config/plugin/provider.ts:73`), the credential is resolved by provider id (`src/model-resolver.ts:324-329`), and `src/plugin/fork/declared-providers.ts` is exhaustive about *which* providers exist, not where they point — so a repository declaring `deepseek.settings.baseURL` sends the operator's key to the host it names while the provider list still reads "DeepSeek". A config-supplied `baseURL` may also interpolate `${ENV_VAR}` from the server's environment (`src/model-resolver.ts:304-312`), and `providers.<id>.package` is npm-installed and imported in-process (`src/plugin/provider/sdk-factory.ts`). Measured end-to-end 2026-10-16 (report: `/tmp/opencode/attack-sec-5/report.md`).
- **Remote `instructions` URLs are fetched at config load.** `ConfigInstructionPlugin` (`src/config/plugin/instruction.ts:138-145`, registered at `src/plugin/internal.ts:263`) GETs every `http(s)` entry in the `instructions` array and injects the response into the model context, so a repository config can make the server dial a URL it names. The fork's own `src/plugin/fork/instructions.ts` resolves only local entries.
- **Goal state is per-session and not copied on fork.** The goal file lives at `~/.local/share/opencode/goals/<sessionID>.md` (`src/plugin/fork/files.ts`), and an id that would resolve outside that directory is refused rather than followed; forking a session or switching worktrees means setting the goal again.
