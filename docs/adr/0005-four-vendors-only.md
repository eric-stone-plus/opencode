# Only Alibaba, DeepSeek, Zhipu and Xiaomi MiMo are supported

This fork runs harness-only against four vendors, so everything else is deleted from source instead of being disabled: the models.dev registry is cut to those vendors (`ModelsDev.restrict`, applied when the registry is loaded, written to the disk cache and embedded at build time), and every other vendor's loaders, V2 plugins, native-LLM adapters, prompts, SDK dependencies and tests are gone. Removal is by vendor, never by transport: `@ai-sdk/anthropic` stays because the Bailian and GLM coding-plan endpoints speak the Anthropic protocol, alongside `@ai-sdk/openai-compatible` and `@ai-sdk/alibaba`. Besides dropping dead code, the 3.4 % registry (15 providers, 312 models instead of 226 and 8,469) is what makes startup and the `/provider` payload small.

Consequence: upstream touches provider code constantly, so every `bun run sync-upstream` will hit modify/delete conflicts on the deleted files. Resolve them with `git rm`; `rerere` only memorizes content conflicts. A merge that adds a brand-new vendor file is harmless at runtime because the registry allowlist still hides that vendor; delete the file anyway. Widening the set means editing the pattern in `packages/schema/src/models-dev.ts` and restoring the code from history.

**V2 (2026-10-12).** In the V2 tree the allowlist regex is applied in `packages/core/src/models-dev.ts` and the bundled snapshot is filtered by `core/script/update-models-snapshot.ts`; vendor code was deleted from `packages/ai` and `packages/core` (about 47 vendor-bound core test cases went with it, and part of the general-behavior coverage they carried still needs re-adding). The transports the endpoints need (anthropic-compatible, openai-compatible, alibaba) stay.
