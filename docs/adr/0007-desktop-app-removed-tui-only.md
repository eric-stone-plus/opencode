# The desktop app is removed and this fork is TUI-only

`packages/desktop` was a pristine upstream copy — the only fork commit that ever touched it is the deletion itself (`5ca9cace6e`, 2026-10-14) — so the app is deleted rather than forked, and every wire that named it went with it: the `@opencode/desktop#test` turbo task; the `build-electron` job, its `publish.needs` entry, its artifact download step and the `TAURI_SIGNING_*` / `LATEST_YML_DIR` / `OPENCODE_DESKTOP_DIST` env it carried in `.github/workflows/publish.yml`; the desktop and electron nix attributes (`flake.nix`, `nix/desktop.nix`, `nix/electron.nix`, and the `packages/desktop` line in `nix/node_modules.nix`); the desktop lines in `.github/CODEOWNERS` and the `OPTIONAL_PACKAGES` loop in `.github/workflows/nix-eval.yml`; the desktop override globs and the "never import the app or desktop packages" wording in `.oxlintrc.json`; the `packages/desktop/` prefix in `script/lint-changed.ts`; the `dev:desktop` and `bench:devex` scripts in the root `package.json`; the devenv benchmark under `packages/app/e2e/performance/devex`; the `.prettierignore` exemption for its generated bindings; and its `bun.lock` rows. `script/sync-upstream.ts` lists `packages/desktop` in `FORK_DELETED_FILES`, so a merge that re-adds it is deleted file by file and `assertForkInvariants` refuses to build or push while it exists again (`script/sync-upstream.ts:94`, `:109`).

Deleted, not disabled — the same policy as ADR 0005 and ADR 0006, and the same consequence (every sync conflicts on the deleted tree; resolve with `git rm`). Nothing depended on `@opencode/desktop`: no manifest imported it, no tsconfig referenced it, and no catalog entry was desktop-only, so the removal is structural rather than behavioral. The supported surface of this fork is the TUI and the CLI that hosts it.

The sweep also covered what pointed *into* the deleted package, not just its name: the app's icon sources moved from `packages/desktop/icons` to `packages/app/icons` (the app still emits its favicon, apple-touch icon, PWA manifest and titlebar branding from them), the `@source` lines that pulled the deleted renderer into Tailwind's scan left `packages/ui/src/styles/tailwind/index.css`, `.github/workflows/nix-eval.yml` lost the optional-package loop whose assignment went first (it would have failed under `set -euo pipefail`), and the changelog's `Desktop` section became `Web` in `script/raw-changelog.ts`, `script/release.ts` and `.opencode/command/changelog.md`.

Kept deliberately, with the evidence:

- `packages/app` stays: the CLI embeds its built web UI. `packages/cli/script/build.ts:69` builds `packages/app/dist` into an archive through `packages/cli/script/app-assets.ts` and links it as `virtual:opencode-app-assets`, which `packages/cli/src/app-assets.ts` serves at runtime (`--skip-web-ui`, which `script/sync-upstream.ts:226` and the seat's rebuild recipe use, embeds an empty archive — `packages/cli/script/app-assets.ts:9` — so the installed binary serves no web shell; the path CI builds is the embedding one). CI exercises that build on every push (`bun run script/build.ts --single --skip-install`, `.github/workflows/test.yml:160`), so deleting the app would break the CLI build.
- `packages/gui-extensions` stays: it is the app's extension host (`packages/app/package.json` depends on it), so it leaves with the app, not before it. Its main-process half has no host in this fork — the desktop app was that host — so the SDK's `main.ts` entries stay typed and tested rather than loaded.
- `packages/session-ui`, `packages/ui` and `packages/storybook` stay for the same chain: `session-ui` renders the app's session screen and is also consumed by `packages/enterprise`; `packages/ui` is the shared component library and holds the five attention-sound assets the TUI bundle needs (`packages/tui/package.json:59`, `packages/cli/src/node/target.ts:41-47`); `packages/storybook` is the component-test harness that both app and session-ui mount as a Playwright `webServer` (`packages/app/playwright.components.config.ts:2`, `.github/workflows/test.yml:270`, `:277`).
- `packages/containers/tauri-linux` stays even though upstream's desktop job built Tauri apps with it: the Dockerfile is a generic Rust + Tauri toolchain base (GTK/WebKit packages), the image is only built by `containers.yml`, which is disabled (`gh workflow list --all`) and triggers on `dev` only, and no workflow here pulls it any more. Deleting it would add a recurring sync conflict and take the container build script's image list with it, for no behavioral gain.

Consequences:

- `nix/hashes.json` still holds the `nodeModules` fixed-output hashes from before the deletion. The FOD's source fileset includes all of `packages/**`, so dropping `packages/desktop` invalidates those hashes, and `nix/node_modules.nix` still carries the `../install` entry whose desktop-era comment is now the only reason given for it; dropping the entry changes the same fileset, so the entry, the comment and the three hashes belong to one deferred pass on a machine with nix. The fork has no nix binary, so this stays open rather than half-done.
- Reviving a desktop app means restoring it from history (`git log --diff-filter=D -- packages/desktop`) and re-adding every wire above, not re-enabling something.
