Motoko plugin symlink target
============================

install.sh creates ~/.config/opencode/plugin/motoko.ts as a FILE SYMLINK to the
path on the first line below. It does NOT copy the file: motoko.ts is a
live-edit window into the motoko checkout. A dangling symlink is non-fatal —
opencode logs "plugin config hook failed" (or a load error) and continues
startup; that is the accepted degraded mode when motoko is not checked out.

Machine A target (install.sh parses the `TARGET:` line below as its default):

TARGET: /home/eric/Documents/Development/private/agent-design/tools/motoko/engine/host/opencode/plugin.ts

On machine B: clone motoko and pass the real path via
`install.sh --motoko-plugin <path>`, or edit the symlink afterwards
(`ln -sfn <path> ~/.config/opencode/plugin/motoko.ts`). Never replace the
symlink with a regular file copy: run-time edits must land in the checkout.

The other two plugin files (block-unsafe-kill.ts, mpskills-update.ts) ARE
regular files and are installed as copies. mpskills-update.ts hardcodes
/home/eric/.local/bin/mpskills-update and is shipped as-is on purpose — see
README "Known portability hazards".
